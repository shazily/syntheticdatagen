If your team needs sample names, addresses, IDs, and other realistic fields inside automated tests, staging databases, or internal tools, the API lets you request that data directly from your own code—no copy-paste from the browser. The fields you define here in the generator are the same ones you send over the API.

What the API does for you

  • See what is available — list supported field types and limits for your plan.
  • Check before you generate — confirm your layout is valid so you do not waste time on a bad request.
  • Download results — get data as JSON, CSV, or line-delimited JSON for spreadsheets or pipelines.

Technical paths: GET /api/v1/capabilities, POST /api/v1/validate, POST /api/v1/generate.

Interactive reference

Browse every endpoint, try requests from the browser, and copy working examples from the live API reference at /api/v1/docs (same site you are on now). If your tools need a machine-readable description, use /api/v1/openapi.json.

Get started in three steps

1. Get a free API key

Open Get a free API key. You will receive a short JSON response with your key (it starts with DATAGEN-FREE-). Treat it like a password—anyone with the key can use your free-tier allowance. If you are on a shared office network, your team may share the same request limits; wait a bit and try again, or reuse a key you already saved.

2. Attach the key to each request

Add an HTTP header: X-API-Key: followed by your key. In the interactive reference, click Authorize, paste the key once, then use Try it out on any operation. Popular clients such as Postman or curl work the same way.

3. Call in a sensible order

Start with capabilities, validate your field list, then generate rows. The interactive reference lists response codes and example bodies for each endpoint.

AI mode (column names only)

POST /api/v1/generate-ai accepts a list of column names. The service infers a canonical data type for each column and fills realistic sample rows (LLM when available, with safe local fallbacks). On the free tier you can request up to 100 rows per call; higher tiers allow larger batches. Use the same X-API-Key header as other endpoints. Details and try-it-out live in the API reference.

For your IT or integration team

The interactive reference can be linked or embedded in your internal wiki the same way you would embed any secure page on this domain. Teams that maintain their own developer portal can import /api/v1/openapi.json into Postman, Scalar, Redoc, or similar products.
